# План: онбординг і профіль

Гілка: `onboarding`. Після кожного кроку відмічай `[x]` і пропонуй commit.

## Що робимо
При першому запуску вступ із 5 екранів, по одному питанню на екран.
Великі кнопки-варіанти, смужка прогресу, кнопка «Назад»:
1. Ім'я (обов'язкове)
2. Ціль: сила / м'язова маса / загальна форма
3. Досвід: новачок / 0,5–2 роки / 2+ роки
4. Тренувань на тиждень: 2–6
5. Власна вага, необов'язково (кнопка «Пропустити»), з підписом
   «для підрахунку вправ з власною вагою»

Після вступу на екрані «Тренування»: «Привіт, {ім'я}!» і прогрес тижня
(«2 з 4 тренувань цього тижня» зі смужкою). Усі відповіді можна змінити
в налаштуваннях.

## Рішення
- Тиждень з понеділка по неділю, рахуємо лише завершені тренування.
- Власну вагу поки лише зберігаємо. Використання в рекордах буде окремою задачею.
- Вкладку «Дані» перейменувати на «Налаштування», зверху картка «Профіль».

## Схема бази
`db.version(1)` не чіпаємо. Додаємо:
```js
db.version(2).stores({
  profile: 'id',   // один запис з id: 1
});
```
Запис профілю:
```js
{
  id: 1,
  name: 'Сева',
  goal: 'strength' | 'muscle' | 'fitness',
  experience: 'beginner' | 'intermediate' | 'advanced',
  workoutsPerWeek: 2..6,
  bodyWeight: 78.5 | null,
}
```
- Міграція: старі таблиці без змін, нова таблиця порожня. Без профілю
  програма показує онбординг (і тим, хто вже користується, теж).
- Експорт: `version: 2`, поле `profile` (об'єкт або `null`).
- Імпорт: приймає version 1 і 2. У копії version 1 профілю немає, тож поточний
  профіль лишається. У version 2 профіль замінюється.
